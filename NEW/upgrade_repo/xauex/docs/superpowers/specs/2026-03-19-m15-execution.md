# M15 Execution Timeframe — Design Spec

**Date:** 2026-03-19
**Status:** Approved

---

## Problem

LEGACY_LEVELS runs on H1 candle closes, producing 0–2 trades per day. The same strategy logic applied to M15 candles yields ~4× more pattern checks per session with no additional code.

## Goal

Switch `EXECUTION_TIMEFRAME` from H1 to M15 so pattern detection runs every 15 minutes instead of every hour. Increase average daily trade frequency while keeping all existing risk controls intact.

---

## Scope

One `.env` change. No code changes. No strategy logic changes.

---

## Change

| Setting | Before | After |
|---------|--------|-------|
| `EXECUTION_TIMEFRAME` | `H1` | `M15` |

All other settings unchanged:
- `LEVEL_PROXIMITY_DOLLARS=3.0` — appropriate for M15 (Gold moves $3–5 per candle near key levels)
- `STRATEGY_MODE=LEGACY_LEVELS`
- Session filter, news filter, risk gates, 1% sizing, max 2 positions

---

## Deployment

1. Set `EXECUTION_TIMEFRAME=M15` in `.env`
2. Restart the bot
3. Run `OBSERVE_ONLY=true` for 1–2 days to review M15 signal quality in the dashboard before enabling live orders

---

## Limitations

**Backtesting:** The backtester hardcodes H1 resampling and cannot simulate M15 trades. `make backtest` results will not reflect M15 behaviour. Validate signal quality via 1–2 days of `OBSERVE_ONLY=true` live observation instead.

---

## Out of Scope

- Tuning `LEVEL_PROXIMITY_DOLLARS` for M15 (revisit if signal quality is poor after observation period)
- Switching or adding strategies
- Changes to the analyst scripts (they read `signal_history` from `state.json` and are timeframe-agnostic)
- Updating the backtester to support M15
