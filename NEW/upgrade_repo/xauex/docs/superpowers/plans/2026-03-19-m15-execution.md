# M15 Execution Timeframe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Switch `EXECUTION_TIMEFRAME` from H1 to M15 in `.env` so LEGACY_LEVELS pattern detection runs every 15 minutes instead of every hour.

**Architecture:** Single `.env` change. No code changes. The bot natively supports M15 — `config.py` validates it, `CandleWatcher` has M15 in its period map, and `_strategy_timeframe()` returns `config.execution_timeframe` for LEGACY_LEVELS. All risk controls (session filter, news filter, 1% sizing, max 2 positions) are timeframe-agnostic.

**Tech Stack:** Python `.env` / python-dotenv

## Post-Deploy Validation (manual, not automated)

After restarting the bot:

1. Confirm `OBSERVE_ONLY=true` is set in `.env` before restarting
2. Start the bot: `python3 -m main` (or however it's normally started)
3. Open the dashboard: `make dashboard`
4. Monitor the **Trading [1]** tab — signals should now appear on 15-min candle closes
5. After 1–2 trading days, review signal quality in the **Analyst [2]** tab (setup scores and morning brief)
6. If signal quality looks good, set `OBSERVE_ONLY=false` to enable live orders

**Note:** Backtesting (`make backtest`) still uses H1 bars and will not reflect M15 signal frequency. Dashboard observation is the only way to validate M15 behaviour.
